# 前端算法之大厂真题解析（二）

## 第二波：更偏「设计感」的五道真题

> 系列收官篇——上一波考「组合」，这一波考「建模」：把模糊的业务描述翻译成数据结构与算法，是高级岗的核心区分点。

## 真题六（字节·设计题）：设计评论楼中楼的数据结构与渲染 ⭐⭐⭐

```
题面: 无限层级评论（楼中楼），支持: 渲染树、按点赞数排序子评论、
     新增评论 O(1) 插入、删除评论后子树仍可访问。
```

**考点识别**：树结构选型 + 「读模型」设计。

**答题分层**：

```
① 存储结构（写友好）: 平铺 Map<id, {parentId, content, likes}>  ⭐
   —— 新增 O(1)；删除只标记 deleted（子树引用仍在——满足"子树可访问"）
② 渲染结构（读友好）: 从 Map 构建 children 树（一次 O(n)），渲染走递归组件
③ 排序: children 数组按 likes 局部排序（每层独立排——楼内排序不动全局）
④ 优化陈述: 读多写少 → 构建结果缓存，写时失效；顶层"分页"用堆或惰性排序
—— 关键洞察: 「写模型与读模型分离」——一份数据两种视图 ⭐⭐
```

## 真题七（腾讯·结构题）：频率计数器 TopK ⭐⭐⭐

```
题面: 实时数据流（埋点事件），随时查询「出现次数最多的 K 个事件」。
     n 可达 10⁷，K ≤ 100。
```

**考点识别**：哈希计数 + TopK 的数据结构选型（algorithm-005 的设计延伸）。

```
分层作答:
① 计数层: Map<event, count> —— O(1) 计数（哈希）
② TopK 层三选一:
   a) 每次查询全排序 O(n log n) —— 查询少可接受
   b) 小顶堆 size=K 维护当前TopK —— 更新 O(log K)，查询 O(K) ⭐ 常规答案
   c) 桶（count → 事件集）: 按次数分桶，查询从高桶往低收集 —— O(n) 空间换 O(K) 查询
③ 边界: 计数会无限增长? → 滑窗内计数（过期衰减）或 LRU 上限 ⭐
—— 加分: 主动说清「更新频繁 vs 查询频繁」决定 b/c 的选型
```

## 真题八（阿里·场景题）：大文件分片上传 ⭐⭐⭐

```
题面: 100MB 文件上传，弱网可用：断点续传、秒传、并发 3、进度回调、可暂停。
```

**考点识别**：分治建模 + 异步调度 + 状态机——js-async-008 的文件版。

```
方案分层:
① 分片: slice(blob, start, end) 切 5MB/片 → 计算整体 hash（秒传的指纹）
② 秒传: hash 先问服务器 → 已存在直接完成 ⭐
③ 续传: 询问已上传分片清单 → 跳过（断点续传的本质 = 跳过已完成 ⭐）
④ 并发: 分片任务进调度器（limit=3，algorithm-008 题③）
⑤ 暂停: AbortController 全量中止；恢复 = 回到③重新询问
⑥ 进度: 已完成字节 / 总字节（分片粒度回调）
⑦ 合并: 全部完成后通知服务端合并（或后端流式写入）
—— 状态机: idle → hashing → uploading(paused ⇄) → merging → done/error
```

## 真题九（美团·建模题）：重叠区间合并 ⭐⭐

```
题面: 促销时间段合并: [[1,3],[2,6],[8,10]] → [[1,6],[8,10]]；
     追问: 任意时刻最多几个区间重叠（并发峰值）。
```

**考点识别**：排序 + 扫描的经典模式（LC 56/253）。

```js
// 合并: 按起点排序 → 尾部比较（尾重叠则吞并）
function merge(intervals) {
  intervals.sort((a, b) => a[0] - b[0]);          // ⭐ 排序创造"可扫描性"
  const ans = [];
  for (const [s, e] of intervals) {
    const last = ans.at(-1);
    if (last && s <= last[1]) last[1] = Math.max(last[1], e);  // 重叠吞并
    else ans.push([s, e]);
  }
  return ans;
}

// 峰值追问: 事件点法 —— 起点记+1、终点记-1，扫描计数取最大 ⭐
function maxOverlap(intervals) {
  const events = [];
  for (const [s, e] of intervals) events.push([s, 1], [e, -1]);
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);   // 同点先-1（闭开约定）
  let cur = 0, best = 0;
  for (const [, d] of events) { cur += d; best = Math.max(best, cur); }
  return best;
}
// 前端化身: 日历排期 │ 滚动加载的预取窗口 │ 直播时间表冲突检测
```

## 真题十（拼多多·综合题）：JSON 结构的深比较 ⭐⭐

```
题面: 实现 deepEqual(a, b)，支持对象/数组/原始值/嵌套；
     追问: NaN 怎么办? 循环引用怎么办? 性能怎么优化?
```

**考点识别**：递归三步曲 + 边界矩阵（js-core-001 的语义 + algorithm-006 的递归）。

```js
function deepEqual(a, b, seen = new Map()) {
  if (Object.is(a, b)) return true;                  // 含 NaN===NaN ✅ ⭐
  if (typeof a !== 'object' || typeof b !== 'object' || !a || !b) return false;

  if (seen.has(a)) return seen.get(a) === b;          // 循环引用: 记录配对 ⭐
  seen.set(a, b);

  const ka = Object.keys(a), kb = Object.keys(b);
  if (ka.length !== kb.length) return false;
  return ka.every((k) => k in b && deepEqual(a[k], b[k], seen));
}
// 加分点: Date/RegExp 的特殊比较 │ key 顺序不敏感 │ WeakMap 而非 Map（回收友好）
// 应用陈述: diff 算法的等值判定、测试断言、React.memo 的深层比较成本警告
```

## 图解总结

```
建模五式:
 楼中楼  → 写模型(Map平铺) + 读模型(树视图) 分离 ⭐
 TopK   → 哈希计数 + 小顶堆/桶（按读写频率选型）
 分片上传→ 分治(切片) + 指纹(hash秒传) + 调度器 + 状态机
 区间    → 排序创造可扫描性 + 事件点±1法
 深比较  → Object.is(纳NaN) + 递归 + WeakMap配对(环)

元能力四把刀: 结构选型 │ 异步编排 │ 边界取舍 │ 分层陈述
```

## 总结

- 建模题的灵魂：写/读模型分离（评论树）、按读写频率选结构（TopK）；
- 分片上传 = 分治+指纹+调度+状态机的标准组合；
- 区间问题两板斧：排序吞并与事件点扫描；
- 深比较的边界矩阵：Object.is 纳 NaN、WeakMap 解环；
- 元能力四把刀：结构、异步、边界、陈述——系列收官的真正交付物。

**面试一句话回答**：设计建模类真题考查把业务翻译成结构与算法的能力。评论楼中楼应做写模型与读模型分离——平铺 Map 支持常数新增与标记删除，渲染时构建树视图并按层排序；实时 TopK 用哈希做计数层，再按更新与查询频率选择小顶堆维护或按次数分桶收集，并考虑滑窗或上限治理无限增长；大文件分片上传是分治切片、整体哈希实现秒传、断点续传等于跳过已完成分片、调度器限并发、AbortController 暂停与状态机管理的标准组合；区间问题先排序创造可扫描性，合并用尾部吞并、并发峰值用起点加一终点减一的事件点扫描；深比较用 Object.is 天然处理 NaN、递归比较键集并用 WeakMap 记录配对解循环引用。所有题目最终都归结为结构选型、异步编排、边界取舍与分层陈述四种元能力的组合。
